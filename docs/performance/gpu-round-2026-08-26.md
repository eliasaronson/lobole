# GPU performance round — 2026-08-26

One day, driven end to end by the owner's HUD screenshots from both GPUs.
The method is the story: build the instrument first, let it justify (or
kill) each optimization, hold every change to a written prediction. Four
ships, one parked finding, two field-falsified assumptions.

## Baseline (owner's session, everything max)

| | Intel Arc (MTL) | RTX 4060 Laptop |
|---|---|---|
| frame | 40.2 ms (24.9 fps) | 17.3 ms (57.8 fps) |
| bound by | the GPU (gpu ≈ frame) | vsync (83% in present) |
| gpu split | shadow 1.45 / ssao 19.56 / main 18.17 | 0.38 / 8.17 / 4.70 |

Feature costs from frame-time deltas (the honest cross-config metric):
full-res SSAO ~12–15 ms of the Arc frame, shadows ~2–5 ms, and a **23.7 ms
floor with both off** — geometry + 4x MSAA, the future MSAA setting's
territory. The NVIDIA has nothing to win on average fps in any config; its
improvable axes are missed-vsync smoothness and watts.

## Shipped, in dependency order

1. **Idle throttle** ([../rendering/idle-throttle.md](../rendering/idle-throttle.md))
   — a resting scene renders at a ~10 Hz event-wait floor; RPCs wake the
   loop (sabotage-checked: wake disabled = 8/8 idle pings blow the bound).
2. **Per-pass GPU timestamps** ([../rendering/frame-timing.md](../rendering/frame-timing.md))
   — availability-only readback riding the frame fence, ~free; caught its
   own first bug via the validation layer (VUID-09401 on first-use slots).
3. **Wake-reason + worst-frame readouts** — the HUD names what keeps the
   loop awake and which phase held the worst frame. Both earned their keep
   the same day (see findings).
4. **SSAO joint-bilateral upsample + per-pixel noise**
   ([../rendering/ssao-upsample.md](../rendering/ssao-upsample.md)) — the
   half tier stops bleeding across silhouettes; the 4x4 noise tile (whose
   blur residual striped curved surfaces at half res) became per-pixel IGN.
   **Field-confirmed: Arc 40.2 → 30.4 ms (24.9 → 32.8 fps) against a
   written prediction of ~31 ms.** NVIDIA unchanged on `full` by design.

## Findings the instruments produced

- **"Idle 0% while hands-off" was agent RPC traffic + screenshot mouse
  motion** — took one reproduction to attribute, after which the wake
  readout was built so the next occurrence names itself.
- **The barrel stripes were NOT the upsample** (pre-change binary renders
  them identically); they were the tiled noise's residual, invisible at
  full res, 8 px stripes at half. Fixed at the source.
- **Laptop DVFS falsifies cross-config per-pass comparisons** (`main` read
  SLOWER with SSAO off on the RTX); pass cost ≠ feature cost (PCF sampling
  lives in `main`, not the shadow bucket). Both pinned in frame-timing.md.
- **Hiding a subassembly costs ~300 ms** — worst-frame readout, first day:
  `update 301 ms` = the full renderer rebuild a visibility toggle triggers.
  **Parked deliberately** ([../known-bugs.md](../known-bugs.md)): the fix is
  an incremental SetInstanceVisible path, and sync granularity is staleness-
  bug territory that wants its own session.
- `fem_async_smoke` failed twice — both under a double-suite machine
  saturation of this round's own making; logged in known-bugs.md with the
  launcher-kept log as the next diagnostic step.

## What remains for the iGPU

An **MSAA setting** (the 23.7 ms floor; riskier — sample count is baked
into every pipeline, so it walks the full swapchain-rebuild path), then
optional: shadow-map 1024 default on integrated, resolution scaling.
Realistic ceiling: ~45–50 fps everything-on at desk resolution; 60 needs
compromises an iGPU's bandwidth sets, not our code.
