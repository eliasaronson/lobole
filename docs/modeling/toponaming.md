# Topological naming

A face or edge of a body has two identities:

- its **index** — the `TopExp_Explorer` order `CADShape::GenerateMesh`,
  picking and the element maps share. It is stable within one shape and
  **not** across regenerations: an upstream edit that adds, removes or
  reorders topology renumbers it.
- its **MappedName** — a string saying *why the element exists*. This is what
  references store, and every regeneration re-resolves it to whatever index the
  element now has.

Every sketch on a face, fillet edge, shell face, up-to-face target, thread,
tolerance, mate connector, drawing dimension and CAM operation stores a name.
A document whose names change between two regenerations of the same input
silently repoints all of them, which is worse than a geometry change;
`tests/test_determinism.cpp` therefore compares element names, not only
volumes, across regenerations of the golden corpus.

## Data model

`src/core/ElementMap.h`:

- `ElementMap` — per body, transient, rebuilt every regeneration, never
  serialized: `names` (face index → name) and `edgeNames` (edge index → name).
  Edge indices follow the deduplicated first-appearance order of
  `TopExp::MapShapes(shape, TopAbs_EDGE)`, the order `GenerateEdgePolylines`
  and edge picking use (a raw explorer walk visits a shared edge once per
  adjacent face). `Resolve(name)` / `ResolveEdge(name)` return `nullopt` when
  the name is gone.
- `ElementRef {featureId, name}` — a persistent reference, serialized as
  `{"feature_id": N, "element": "4/g7"}`. `featureId` is the id of the feature
  whose **body** owns the name (the body's `createdBy`), which is not
  necessarily the feature that made the face: a hole cut into a box leaves its
  bore on the box's body. Resolution finds that body and looks the name up.

## Naming grammar

A name is a plain readable string; nothing hashes it. A step appends and never
rewrites the prefix, so a name records its derivation.

```
name  := seed (';' step)* ('#' instance)?
seed  := tag '/g' entityId       side face swept from sketch entity <entityId>
       | tag '/g' entityId '.' glyph '.' contour '.' seg
                                 side face swept from one segment of a text
                                 label's glyph (glyphs counted over rendered
                                 characters only)
       | tag '/g' entityId '@h2' the same, on a herringbone extrude's upper
                                 half (README.md#twisted-extrudes)
       | tag '/cap0' | '/cap1'   extrude/revolve start and end caps
       | tag '/cap0@g' key       caps of one profile group of a multi-profile
                                 sketch (key = its outer loop's lowest entity
                                 id, plus '.' glyph '.' contour for a text
                                 label's letter)
       | tag '/pole' n           a revolve's degenerate pole edge at the axis
       | tag '/seam' i           boolean section edge history did not name
       | prefix '/face' i        a primitive, import or rebuilt shape (below)
       | tag '/p' entityId '/' role
                                 a hole's face by role (bore, bottom, counterbore,
                                 counterbore_floor, countersink, point -- a
                                 blind floor's drill point; '.n' when one
                                 role is in pieces), per sketch point; a face
                                 with no role is '/p' entityId '/face' k
       | tag '/' role            a generated bearing's face by role (bore,
                                 outside, inner_side_a|b, outer_side_a|b,
                                 shield_a|b; docs/parts/README.md#bearings),
                                 a generated retaining ring's (ring_side_a|b;
                                 its bore and outside as a bearing's), or a
                                 retaining ring groove's (groove_floor,
                                 groove_flank_a|b;
                                 docs/parts/README.md#retaining-rings)
step  := 'M' tag piece?         modified by feature <tag>
       | 'G' tag piece?          generated by feature <tag> (a blend face from its spine edge)
       | 'S' tag                 carried to the far side of jog <tag> (its near half has none)
       | 'U' i                   fallback: an unnamed edge of a named face
       | 'L'                     fallback: a face named from its boundary edges
piece := '[' stem ('|' stem)* ']' ('.' i)?
                                 one of the pieces one input became, by the
                                 faces only it touches (below)
       | '.' i                   ... by position, where nothing else told the
                                 pieces apart
```

`[`, `]` and `|` appear nowhere else, and the content of a bracket is opaque:
its names carry `;`, `,`, `/` and `#` of their own, so every reader splits a
name with the one bracket-aware tokenizer, `topo::NameSteps`
(`src/core/ElementOrigin.h`).

`tag` is the owning feature's id, so two features' elements never collide when
bodies combine. `entityId` is the sketch's stable entity id (monotonic, never
reused), which is what makes the names stable: moving, resizing or reordering
sketch entities keeps the names, and adding a hole never renames a cap because
caps are fixed sentinels. Deleting the entity removes the name.

A text label is ONE sketch entity drawing many glyph segments, so its side
faces carry the sub-index: the third segment of the second contour of the
first letter of label 9, cut by extrude 4, is `4/g9.0.1.2`. It decodes as a
side face of entity 9 like `4/g9` would. Editing the string renames the faces
of the letters after the edit (their glyph index or contour count changed);
anything that must survive a text edit targets the entity, `g<textId>`, as
CAM does.

Examples: extrude 4 over line 7 gives side face `4/g7` and caps `4/cap0`,
`4/cap1`; a fillet 5 on an edge of it gives a blend face `<edge name>;G5`;
the same side face after cut 6 goes through it is `4/g7;M6`; the third copy of
a pattern is `4/g7#2`, a mirror's `4/g7#m`; the right half of extrude 2's
top, after slot 4 cut it in two, is `2/cap1;M4[2/g3|4/g3;M4]`.

### Split pieces

When one operation turns a face or edge into several, each piece is named by
the faces only it touches (`QualifyPieces` in `ElementHistory.cpp`, run after
the history pass and before the fallback passes). A **face** piece's bounds
are the named faces sharing an edge with it; an **edge** piece's are the
named faces at its end vertices that do not contain it, so the top edge of a
front wall is told apart by the same walls that tell the top's pieces apart.
Each neighbour enters by its **stem** (`topo::PieceStem`: its name with every
piece qualifier and piece ordinal removed), so names nest one level at most;
a face not yet named when it runs (an L face) does not count. A piece's
qualifier is its bounds less those every piece of the group shares, sorted,
joined with `|`:

```
2/cap1;M4[2/g3|4/g3;M4]      the right piece: the block's right wall, the slot's wall
2/cap1;M4[2/g5|4/g5;M4]      the left piece
2/g2;U3;M4[2/g3|4/g3;M4]     the right half of the front wall's top edge
```

A moved or resized cutter keeps those names exactly, and so does a second
cutter elsewhere: the same faces still bound the same pieces. Pieces whose
qualifiers come out the same are numbered `.0`, `.1` in result order behind
it, and ones nothing of their own tells apart (every bound shared) are
`<name>;M<tag>.<i>` -- an **ordinal** name, by position, which a reorder of
the pieces would move. A last pass leaves no two faces, and no two edges, one
name: the first keeps it, the next take `.1`, `.2`.

An edge a piece face's U pass names carries the qualifier with it,
`2/cap1;M4[2/g3|4/g3;M4];U0`.

## How each operation names its output

`src/core/ElementHistory.{h,cpp}` (namespace `topo`) and
`src/core/sketch/SketchProfile.cpp`. Every operation keeps its OCC maker alive
and folds its `Modified`/`Generated`/`IsDeleted` reports into one
`BRepTools_History`, so propagation is one code path.

- **Extrude / revolve** (`BuildPrismNamed`, `BuildThinPrismNamed`,
  `BuildRevolveNamed`): side faces from `Generated(profileEdge)`, matched back
  to their sketch entity; caps from `FirstShape()`/`LastShape()`. Revolve pole
  edges have no generating parent and are named by position.
- **Booleans** (`topo::BooleanNamed`, used by `Boolean`, body modes, rib,
  patterns): a face the operation leaves untouched keeps its name; `Modified`
  appends `;M<tag>` (`.i` on a split); `Generated` appends `;G<tag>`; section
  edges history misses get `<tag>/seam<i>`. In OCC 7.9 faces created along an
  intersection are reported as `Modified`, and a pierced face *generates* its
  section edges. A clean-up that belongs to the same operation
  (`topo::RefineResult`, e.g. a modelled thread merging the footprint its
  square end draws on a shoulder) has its history composed onto the
  boolean's before naming, so pieces it merges take their original's one
  name and every face it leaves alone is named as the bare boolean names it.
- **Refine** (`RefineFeature`, ShapeUpgrade_UnifySameDomain): named through
  the unifier's history (`topo::NamesThroughHistory`, the one-input
  overload). The unifier rebuilds every face whose edges it merged and
  reports it `Modified`, so a result face that exactly ONE input face
  became keeps that face's name verbatim; faces it merged take one of
  theirs with `;M<tag>`. It used to rename every face `<id>/face<i>`, which
  broke every reference to the body -- a study's loads, a bearing's seat, a
  mate -- for the sake of the seams it cleaned.
- **Fillet / chamfer** (`topo::EdgeBlendNamed`): blend faces
  `<spine edge name>;G<tag>`; support faces keep their names through
  `Modified`; corner patches fall to the fallback passes. The spine edge itself
  is consumed, so a reference to it stops resolving.
- **Fallback passes** (`topo::ApplyFallbackPasses`), run after history: **U**
  — a named face names each unnamed boundary edge `<face>;U<k>`, which is what
  gives edges (fillet spines) stable names; **L** — a still-unnamed face takes
  its sorted boundary-edge names joined with `,` plus `;L`.
- **Primitives and rebuilt shapes** (`topo::NamePrimitiveElements`): every face
  `<prefix>/face<i>` in index order, then the fallback passes. Used by
  Import, the stored Box/Sphere/Cylinder an older document carries
  ([primitives](README.md#primitives)) (a multi-body import adds a body ordinal,
  `<tag>/b1`) and by features that rebuild topology wholesale — split, sweep,
  loft, pipe and rib tools, fasteners.
- **Shell and draft** are named through their builder's own history
  (`topo::HistoryArguments` + `topo::NamesThroughHistory`): a face left alone
  keeps its name, a moved one takes `;M<tag>`, a shell's inner wall is
  `<outer face>;G<tag>`. Index-order names numbered the faces in the order the
  builder handed them back, which changes from run to run, so a draft on a
  shelled body's inner wall picked another face after a rebuild.
- **Holes** (`HoleFeature::NameByRole`) name each drilled face by what it is,
  keyed by the sketch point it was drilled at: `<hole>/p<entity>/bore`, and
  so on. Deleting one point renames none of the other holes. These names
  are stable while the operation produces the same topology in the same order,
  not across a change that reorganises it.
- **Patterns** (`PatternFeature.cpp`): instances take the source's names with
  `#<instance>`; the fused result is split back into solids by looking each
  piece's faces up in the fused map (`topo::NamesOfSubShape`) — the pieces
  share their faces with the shape they came out of, so no second history pass
  is needed. The marks the seed's faces carry (a hole's, a thread's) are
  given to each instance's face of the same name less its `#<instance>`
  ([holes and threads](holes-and-threads.md#hole)).
- **Derived** copies rename the source's elements
  `<derived id>/<source created_by>/<source name>` ([derived.md](derived.md)).

A MappedName is compared whole almost everywhere. The one reader of the
grammar is `topo::DecodeElementName` (`src/core/ElementOrigin.h`): it says
which feature made an element (the seed's, or the last G step's), its role
(start or end cap; side, and its sketch entity; generated -- a fillet's or
chamfer's face, or one a boolean made along a seam; a hole's roles; pole;
seam; positional; or boundary for an L face), the Derived copies it came in
through, its pattern instances, what modified it since, and -- for a piece --
`piece`: what it is a piece of, the neighbours its qualifier names, and
whether it is ordinal. A qualifier's names are not the element's: the
decoder, `FeatureIdsMentioned` and drawing provenance read past them.
`topo::DescentOf` says how a current name descends from a stored one --
modified by whole `;M<tag>` steps, split (a step with a qualifier or an
ordinal), or otherwise. Drawing provenance and a
tapped hole's thread record read names through it.

`list_elements` reports each element's `made_by` and `role` from it, and
filters by them: `made_by` (a feature id or name; a pattern means its
source's faces, every copy), `role` (`floor` and `walls` read as `end_cap`
and `side`), `entity`, and `via` -- a Derived feature, with `made_by` then
naming a feature of the source part. A filter that matches nothing answers
`why`: the roles that feature did make, or that it made no face here. Each
edge also lists the `faces` it joins by name (one for a seam): an edge's own
name comes from whichever face named it first, so "the edges where the top
meets the walls" is asked of those, not of the edge's name. A piece (a face
or an edge, not the U edges of a piece face) carries `piece` {`of`,
`bounded_by`, `ordinal`}; `ordinal: true` says its name is by position and
will not survive a reorder of the pieces.

An unnamed face cannot be picked, threaded, filleted, fitted or measured by
reference, and `list_elements` omits it; its `unnamed_faces` count is what says
whether the listing is complete.

## Resolution and failure

References resolve against the body of the feature they name, so features added
downstream never disturb them; only editing that feature or its ancestors
exercises name stability. A name that no longer resolves is a feature error
naming the element — never a silent snap to a neighbouring face. Repair is
re-picking: Reattach face… for a face-attached sketch, Pick edges… for a
blend.

### Resolving a name

`ElementMap::Resolve` and `ResolveEdge` (`src/core/ElementOrigin.cpp`, every
caller) look a name up in three steps:

1. **exact** — the name.
2. **the same piece** — a stored `<stem>[a|b]` finds the one current piece of
   `<stem>` whose qualifier holds `a` and `b`: the piece the reference meant,
   whatever the other pieces now are, so it resolves silently. When `<stem>`
   names one whole face again (the cutter no longer splits it), that is the
   piece grown to the whole, and it resolves too.
3. **a positional name** — a stored `<stem>.<i>` with no exact match, saved
   before pieces were named by their neighbours, takes the i-th piece of
   `<stem>` in result order, the rule the build that saved it used. The
   regeneration warns on the feature holding it (a `PositionalLookups` scope
   around each feature's Execute, `Document.cpp`) that it is by position and
   to re-pick it.

Anything else does not resolve. Why is said by one helper,
`topo::UnresolvedReason`, which every feature that resolves a face or an edge
calls (`tests/test_conventions.cpp` fails on the old literal anywhere else):
"`<what> '<name>' no longer exists`", or, when what it named is now several
pieces and none or more than one is bounded by all it was bounded by,

> attached face '2/cap1;M4[2/g3|4/g3;M4]' was split by Slot (4) into
> '2/cap1;M4[2/g3|4/g7;M4]' and '2/cap1;M4[4/g3;M4|4/g9;M4]'; pick the one
> you meant

naming the pieces that hold any of its old bounds. A second slot through the
right piece is that case: the sketch on it and the fillet on its edge fail,
where a positional name moved both onto a 2 mm sliver and reported success.
It never picks the nearer piece.

An assembly's references resolve against the part's FINAL body, so a
feature added after them does reach them. A mate connector still fails,
suggesting the names that extend its own. A fastener's seat follows the one
face its name became through whole, unsplit `;M<tag>` steps -- the same
face, modified (a chamfer on its rim) -- and fails on a split
(`;M<tag>[…]` or `;M<tag>.<i>`), naming the feature that split it
([attached and mated](../parts/README.md#attached-and-mated)).

A face appearance (v164) also resolves against the FINAL body — its name is
looked up in the creating feature's body after every feature, so a face a
later cut made can carry one — and follows a face a later feature modified
or split to every face whose name extends it by `;M<tag>` steps. A name that stops resolving is not a feature
error, since the geometry is fine: it is a warning in the regeneration
summary and `face_appearance_unresolved` in `get_state`, and the override is
kept until it is cleared or resolves again
([a face of its own](../rendering/materials.md#a-face-of-its-own)).

Edge picks for a blend are stored against the blend's **input** body, not its
displayed output (whose names already carry the blend's own tag):
`Document::CachedBodiesAfter` supplies the input, and
`topo::ResolveEdgeOnBody` maps the picked edge onto it by name or, failing
that, by an interior point of the edge (`PolylineArcMidpoint` — an endpoint is
shared by every incident edge and would match an arbitrary one).

## Picking

`FaceSelector` (`src/cad/FaceSelector.cpp`) maps a ray to a face index
(`PickFace`) or an edge index (`PickEdge`: ray-to-polyline by angular error,
rejecting occluded edges; ties go to the nearest edge, which matters looking
straight down a bore where every rim is collinear with the ray). The index is
turned into a name through the body's `ElementMap`.

## Tests

`tests/test_toponaming.cpp` is mutation tests: build a model, capture
references, apply an upstream edit (dimension change, entity added, entity
deleted), regenerate, and assert each reference resolves to the geometrically
right element or fails exactly when it should -- among them a slotted block's
pieces under a moved, resized and added slot, a base drawn from the other
corner, and a positional name from an older file.
`tests/test_element_origin.cpp` decodes qualified names. `tests/test_fillet.cpp` covers
blend naming and dangling edges; `tests/test_toponaming.cpp` also pins pattern
instance names; `tests/test_determinism.cpp` name stability over the golden corpus.

## Limits

- Pieces nothing tells apart (every face that bounds one bounds all) keep a
  positional `.i`; `list_elements` says `ordinal: true` for them.
- A piece's qualifier is checked against its neighbours' names, so a change
  that renames the neighbours themselves (a base sketch redrawn from the other
  corner, its lines now on other sides) makes the reference fail rather than
  follow it.
- No references into a pattern as a structure: the `#i` suffix names a face of
  an instance; there is no queryable instance list.
- No geometric-similarity suggestion when a reference dangles; repair is a
  re-pick.
