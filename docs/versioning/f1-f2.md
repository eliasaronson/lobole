# F1 + F2 — Format spec, golden corpus, autosave — design

> **SHIPPED 2026-07-10** as designed.

The insurance milestones, now overdue by the plan's own standard: the format
churned **v9 → v17 in one week** of modeling milestones, and real models now
get produced daily (humans + MCP agents). Estimated **~2 days** total.

## F1 — Format spec + golden-file corpus (~1 day)

### The spec (`docs/versioning/format.md`)

Not a duplicate of `Serialization.cpp` — the spec documents the **contract**,
the code stays the source of truth for field lists:

- The envelope: `{format: "designer-document", version: int, parameters?,
  features[]}`; unknown-newer versions refuse to load (already enforced,
  `Serialization.cpp:767`).
- **Id-stability guarantees**: feature ids are unique per document and never
  reused; sketch entity ids are stable per sketch (grow from 1, datum block
  at 0xFFFFFF00); element names are derived (transient) and NOT serialized —
  a written statement of what a file may rely on.
- **The migration policy, codified**: every `kVersion` bump ships (1) a
  loader migration (never a save-side compatibility mode), (2) a golden file
  for the *previous* version, (3) a round-trip test. This is de-facto
  practice; writing it down makes it reviewable.
- A version history table (v1 → v17, one line each) — reconstructed from the
  migration branches in `FeatureFromJson` and git history.

### The golden corpus (`tests/golden/`)

Historical saves don't exist for most versions, so the corpus is
**synthesized from the loader's own migration branches** — each file is
minimal but exercises one era's quirks:

- `v01-plain-box.json` — no ids anywhere (Document assigns).
- `v03-sketch-index-refs.json` — entity ids absent, constraints by index
  (the legacy-migration branch), plus a rigid `rect` entity (expanded to four
  lines on load).
- `v09-sketch-extrude.json` — the plan-era baseline: solved sketch,
  constraints with ids, extrude by sketch_id.
- `v11-expressions.json`, `v12-plane-ref.json`, `v14-boolean.json`,
  `v15-pattern.json`, `v17-full.json` — one per major addition; `v17-full` is
  a kitchen-sink part (variables, datum plane/axis, revolve, boolean,
  pattern, fillet-by-element-ref).

ctest `golden_corpus` (label-free — runs on CI): for each file, load →
regenerate → assert feature count, body count, and volumes to tolerance
(values pinned in a sidecar `.expect.json` so the test data is readable).
Plus a **round-trip test**: load each golden, save at v17, reload, assert the
same geometry — proving migrations compose with the current writer.

Corpus construction is verified honest by a one-off check: hand-write each
file, confirm the intended migration branch is actually hit (coverage via
temporary logging), then freeze.

## F2 — Autosave + crash recovery (~1 day)

### Dirty tracking

`Document::Version()` already increments on every mutation. `AppState` gains
`lastSavedVersion` (set by save/open/new) — dirty = `Version() !=
lastSavedVersion`. This also fixes a latent gap: nothing warns about unsaved
changes today (that GUI prompt is not in scope here, but the tracking is the
prerequisite).

### The autosave loop

- Command layer first: a `core`-side `Autosaver` (testable, GUI-free) with
  `MaybeSave(doc, projectPath, now)` — fires when dirty AND interval elapsed
  AND the document changed since the last autosave.
- Sidecar next to the project: `part.json` → `part.json.autosave`. Unsaved
  documents go to one well-known path under the XDG state dir
  (`~/.local/state/designer/unsaved.autosave.json`).
- **Atomic write**: save to `<target>.tmp`, `rename()` over the sidecar —
  a crash mid-write can never corrupt the previous autosave.
- Cleared on clean save and clean exit.
- Pumped from both main loops (GUI frame loop and the headless loop — RPC
  sessions deserve the same insurance), default interval 60s, `--autosave
  <seconds>` flag (0 = off) so tests can run it at 1s.

### Recovery

- Core: `Autosaver::FindNewer(projectPath)` — sidecar exists and is
  newer-than/absent-project.
- GUI: on open (and on startup file load), a modal offers "Recover autosaved
  changes?" → loads the sidecar in place of the file (document is then dirty,
  pointing at the original path).
- RPC/headless: `open_project` response gains `autosave_available: true` when
  a newer sidecar exists; recovering = `open_project {path: <sidecar>}` — no
  new verbs needed, and agents see the same signal humans do.

### Tests

Unit: dirty tracking, interval/no-change suppression, atomic-write leaves no
`.tmp` behind, FindNewer logic. Integration: a `headless_smoke` block —
model, autosave at 1s, SIGKILL (not TERM) the app, restart, assert
`autosave_available` and that the sidecar reloads with the pre-kill volume.

## Order & risks

F1 before F2 (the corpus pins behavior the autosave writer must not disturb).
Risks: golden files drifting into "whatever the loader accepts" rather than
what old writers produced — mitigated by deriving each file from a specific
migration branch and freezing them (they are never regenerated by tooling);
autosave interacting with `--gui-tests` determinism — tests run with
autosave off by default (`--autosave 0` in the harness).
