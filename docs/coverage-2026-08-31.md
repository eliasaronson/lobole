## The caveat: app-only code reads as untested, and is not

**`gcov` counters are written when a process exits normally. Every smoke test
stops the app with `terminate()` (SIGTERM), and nothing installs a handler for
it — so the app's own runs contribute NOTHING to this report.**

The tell is `src/core/io/Checkpoints.cpp`, which appears below with all 8 of
its functions "never called". Checkpoints are goal #1 of this project's
vision, and they are thoroughly tested — by `tests/headless_smoke.py`, phase
"Checkpoints", which creates, lists, mutates, restores and exercises the error
paths, and which **passed in this very run** (17.24 s). The counters are zero
because the app it drove was killed before it could flush them.

So the list below is really *"functions `designer_tests` never calls"*, and
everything reachable only through the RPC surface is missing from the picture.
Anything on it that has a python smoke is a false positive.

**The fix**, for whoever picks this up: install a SIGTERM handler in coverage
builds that calls `__gcov_dump()` before exiting. It is small and it makes the
report mean what it says. Until then, cross-check any candidate against
`tests/*.py` before believing it.

Two lesser caveats:

- Three of the heaviest tests hit their ctest TIMEOUT under `-O0` +

  fits into is still an island` (623 s), `cam: clearing the outline still goes
  around material` (407 s), and `offscreen_smoke`. Their paths are therefore
  partly unmeasured. The timeouts are sized for the normal build, where those
  run in 54 s and 35 s.
- 256 of 267 instrumented objects produced data.

### What is worth reading in it, once the false positives are set aside

A lot of it is destructors, trivial accessors and template instantiations that
gcov counts as separate functions — noise, not gaps. What survives that
filter, and is genuinely worth a look:

- **Removal and teardown paths.** `RemoveConfigurationCommand::Execute`/`Undo`,
  `Document::RemoveCamSetup`, `AssemblyDocument::RemoveConfiguration`,
  `SketchFeature::RemoveExternalGeometry`, `GitVault::RemoveRemote`. A
  consistent shape: we test that things can be created and rarely that they can
  be removed, and removal is where dangling references live.
- **`Command::Description()` overloads** for Add/Modify study and feature —
  these are what the History panel and F11's "what changed" print, so a wrong
  one is a version list that misdescribes itself.
- **Availability probes** — `fem::SolverAvailable`, `fem::ModalAvailable`,
  `fem::Available`, `cam::PostExists`, `cam::PostIds`. Cheap to call and each
  one gates a refusal message.
- **`Measure::CheckGeometry`'s lambdas and `NearestPointOn`** — the geometry
  validity check itself, which is the thing an agent is told to trust.
- **`cam::RederiveDepths`** — depths are derived, not typed, and this is the
  function that re-derives them when the model moves under a job.

None of these is a bug on its own. They are the places a bug could sit
indefinitely without any test noticing, which is the whole question this tool
answers.
